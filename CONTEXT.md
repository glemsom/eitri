# Eitri — Domain Glossary

Canonical terms for planned Eitri (single-binary AI coding agent for Linux).

- **Workspace** — the user's working directory in which Eitri reads, writes, and executes; mounted read-write at its host path inside the sandbox.
- **Path namespace** — the view of the filesystem a component operates in. Host paths are canonical; the only remapped region is the session temp (`/tmp` ↔ host `/tmp/eitri-<GUID>`). See ADR-0002.
- **Session temp** — per-run ephemeral `/tmp` shared by `bash` and host-side tools; removed at run end.
- **Sandbox / bwrap cage** — the bubblewrap isolation boundary for shell commands; root read-only, workspace + session temp writable, separate PID namespace, fresh pid-scoped `/proc`, private devtmpfs `/dev` with writable `/dev/shm`.
- **Host-side tool** — a tool running outside the bwrap cage but resolving the same path namespace as `bash` (e.g. `read`, `write`, `edit`, `open_in_browser`). Write-side tools (`write`, `edit`) also gate targets on the writable roots; `read` and `open_in_browser` are read-only and resolve through the shared translator alone.
- **Slash-skill activation** — a human-invoked skill trigger from the TUI via `/skillname [<args>]`, distinct from the model's automated `skill` tool call. The activation run produces a structured payload (`<skill_content>` plus optional `<skill_resources>`). With args, the payload is **skill-injected** into the model's context for the follow-up args turn so the model acts on the args with the skill instructions loaded; a bare `/skillname` injects only the note and queues no turn.
- **Drag selection** (T6, issues #124/#261) — `internal/tui` click-drag over the history viewport marks a cell range in reverse video and copies the marked plain text. Selection coordinates are **rune-indexed and width-aware**: a mouse cell arrives in screen display-width space, `colToRuneIndex` converts it to a rune index into the plain line, and highlight (`highlightRange`) and copy (`copySelection`) both operate in that same rune space — never in display-width or byte space — so wide/multibyte characters (CJK, emoji, unicode arrows, smart quotes) are selected, highlighted, copied, and pasted exactly, with no boundary split or under-coverage (#261).
- **Scroll-region seam** (issue #391) — the Transcript owns the one region computation (`scrollRegionHeight`, terminal height minus the fixed bottom band) and the hit-test that reads it back (`contentLineAtScreenRow`: is a screen row inside the history region, and which content line does it map to). The render path sizes the persisted history viewport through the same seam, so the selection/mouse side (`mouseToContent`) maps through the already-rendered window instead of recomputing the region from Model width math — one region source serves both render and input, so drag coordinates and on-screen rows can never drift apart.
- **Tool-result byte cap** (issue #286) — the shared byte budget (`DefaultByteCap`, 64 KiB) every tool result is measured against at the tool-result boundary before its bytes enter message history: over-budget results are deterministically head-truncated with an explicit `+N bytes truncated` marker (composing with the line compressor's `+N more` marker into a merged `+N more, +B bytes truncated` tail — never silent), while the full raw result stays available through the TUI expand seam (`ToolResultEvent.Result`), so only the *delivered* form is capped.
- **Expanded-view mode** (T1/T3, issues #273/#275) — the persistent Ctrl+E transcript mode (`expandAll`) that renders every tool entry full-size. In the mode, an `edit`/`write` card replaces its raw result dump with an **inline card diff**: the entry's captured before→after file content (issue #90 fields) runs through the pure-Go diff engine (`internal/diff`) and the inline card diff styling (`renderDiff`, `renderWordDiff`, homed in `internal/tui/diff.go`) inside the card's category-colored left border. A path whose content the engine couldn't snapshot falls back to the `[+N, −M]` count summary. Collapsed, the card keeps today's one-line `[+N, −M]` delta tag and never leaks file content. Ctrl+E is the **single expansion mechanism**: the modal changed-file review overlay and its Ctrl+D toggle are gone (issue #276), so Ctrl+D is deliberately unbound (it reads as "exit" in other tools) and file-change inspection happens only in-flow on these expanded cards.
- **Thinking suppression** (issue #265) — the per-provider capability to actually stop chain-of-thought on the wire when the thinking toggle is off, declared through the generation-control seam (`GenerationControlThinkingSuppression`, negotiated via `NegotiateGenerationControls`). The two expression forms are both suppression: the openai-compatible path (opencode-go / custom-openai) **omits** the `thinking` toggle when off (issue #54), while the copilot path sends an explicit `thinking:{type:disabled}` (issue #263). A provider that does not declare the control surfaces a settings-panel warning that reasoning cannot be disabled instead of silently no-op'ing the toggle.
- **open_in_browser escape hatch** (issues #90/#276) — deliberately **dropped**. The modal review panel's `o` key that handed the focused changed file to the host browser/editor was the only consumer of the TUI's `OpenInBrowser` dependency seam, so both went with the panel (decision recorded per issue #276 AC5). The standalone `open_in_browser` host-side tool (registry-backed) remains for model-invoked opens.
- **Stopped turn** (issue #315) — a running agent turn aborted by the user (esc or ctrl+c in the TUI) at the context-cancellation boundary: the provider stream dies and any running tool is killed, and the engine refuses to open fresh provider work. The partial output already produced stays on screen in its own pane with a stopped marker — distinct from an error — and the next prompt runs normally. The TUI owns the cancel handle; the engine reports the stop through a sentinel (`ErrStopped`, wrapping `context.Canceled`) that the app adapter maps to the TUI's `Stopped` result flag so the two layers stay decoupled.
- **TurnDispatch** (issue #341) — the TUI module (`internal/tui/turn_dispatch.go`) owning the turn state machine: context lifecycle for each agent turn (install, cancel, release), streaming delta accumulation into the in-progress assistant message, and `turnDoneMsg` reconciliation (stopped, error, success with or without streaming). Depends on the **Turn** seam — the engine interface (`type Turn func(ctx, prompt, payload) (TurnResult, error)`) — injected at construction via `NewTurnDispatch`. Continuation logic (`continueReq` / `continueResp` / prompting) remains on **Model**, not on TurnDispatch.
- **Phase** (issue #363) — the single derived answer to "what is the agent doing right now", computed on the TUI side (`internal/tui/phase.go`) from the live turn state rather than stored: the turn's busy flag plus what the in-progress assistant stream is doing. The four values are `idle` (no turn runs), `reasoning` (chain-of-thought is streaming before the answer begins), `working` (a turn runs but no assistant text streams yet — the tool-heavy gap), and `answering` (answer text is flowing; it takes precedence over trailing reasoning). Transcript's `phase()` is the seam the stage-label verb (issue #365) and the live-reasoning panel (issue #364) hang off; the busy indicator's stage verb (issue #365) splits by phase — `Reasoning` / `Working` / `Answering` under the spinner — while the reduced-motion/ASCII fallback stays the static `… thinking` line.
- **Live reasoning panel** (issue #364) — the current turn's reasoning block auto-expands while its chain-of-thought deltas stream, framed in the dimmed streaming pane border, so the user watches the thinking grow live instead of a static hint; it collapses back to the one-line `🤔 N tok` hint once the turn's answer lands. The expansion is computed at render time from the message's still-streaming state (`msg.streaming && msg.reasoning != ""`) rather than stored, so it needs no stream-exit reset: tab still toggles the block during and after streaming (collapsing a live block through the per-turn collapse override), and any reasoning the backend sneaks through a thinking-off turn stays hidden behind the `thinkingRequested` gate.
- **Tool-activity pulse fallback** (issue #366) — the busyPulse accent flash on tool starts while thinking is off: with no chain-of-thought stream to derive the arrival pulse from (the stream-delta pulse in `appendStreamDelta`), each tool beginning execution arms the same brief 3-frame accent pulse so the running (incomplete) tool entry's head flashes the agent accent instead of its category hue. Gated to thinking-off turns (thinking-on already pulses via the stream) and to the motion gate, so the reduced-motion/ASCII fallback keeps the static `… thinking` indicator and the category-colored entries; a completed entry settles back to its category hue immediately.
