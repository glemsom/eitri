# Eitri — Domain Glossary

Canonical terms for planned Eitri (single-binary AI coding agent for Linux).

- **Workspace** — the user's working directory in which Eitri reads, writes, and executes; mounted read-write at its host path inside the sandbox.
- **Path namespace** — the view of the filesystem a component operates in. Host paths are canonical; the only remapped region is the session temp (`/tmp` ↔ host `/tmp/eitri-<GUID>`).
- **Session temp** — per-run ephemeral `/tmp` shared by `bash` and host-side tools; removed at run end.
- **Sandbox / bwrap cage** — the bubblewrap isolation boundary for shell commands; root read-only, workspace + session temp writable, separate PID namespace, fresh pid-scoped `/proc`, private devtmpfs `/dev` with writable `/dev/shm`.
- **Host-side tool** — a tool running outside the bwrap cage but resolving the same path namespace as `bash`. Write-side tools gate targets on the writable roots; read-only tools resolve through the shared translator alone.
- **Slash-skill activation** — a human-invoked skill trigger from the TUI via `/skillname [<args>]`, distinct from the model's automated `skill` tool call. The activation run produces a structured payload (`<skill_content>` plus optional `<skill_resources>`). Every `/skillname` starts an agent turn with the payload folded into the single high-priority **user** message that carries the prompt; trailing args become the turn prompt, and a bare `/skillname` falls back to a default `apply the <name> skill` prompt. Delivering the directive in the user layer (adjacent to the prompt) rather than as a competing second `system` message lets it outrank the Eitri persona when instructions conflict. Session compaction keeps the skill-carrying leading user message in the stable head, so a slash-skill stays effective across eviction-and-summary. A repeated `/skillname` **re-applies** the full payload rather than no-op'ing: it activates through a force-re-inject path (`Registry.ActivateSkill`, distinct from the model-tool `skill` call) that bypasses the session-lifetime dedupe. The dedupe still guards the model's *automatic* `skill` tool call within one turn-loop, never fewer re-injections for a human slash.
- **Drag selection** — the width-aware click-drag copy seam lives in its own module (`internal/tui/selectionweaver.go`): the `selectionWeaver` value type owns the selection store (active flag plus anchor/end cell range), the rune-index conversion (`colToRuneIndex`), and the rune-space highlight/copy operations. Selection coordinates are **rune-indexed and width-aware**: a mouse cell arrives in display-width space, `colToRuneIndex` converts it to a rune index into the plain line, and highlight and copy operate in that same rune space — never display-width or byte space — so wide/multibyte characters are selected, highlighted, copied, and pasted exactly. The seam is a pure value type: the Model/Transcript seed it via `start`/`move`, feed it the plain content lines, and read back highlighted/copied text, so it is unit-testable on its own.
- **Scroll-region seam** — the one region computation lives in its own module (`internal/tui/scrollreg.go`): the `scrollRegionHeight` function (terminal height minus the fixed bottom band) and the `scrollRegion` value type's hit-test (`contentLineAtScreenRow`) and region-membership check (`inRegion`). The Transcript is a thin delegate; both mouse inputs route through it: click-drag selection maps rows through the already-rendered window, and wheel scrolling only scrolls when the pointer is over the region — so one region source serves render, drag, and wheel, and drag coordinates and on-screen rows never drift apart.
- **Scroll / follow** — the history viewport's auto-follow behavior for long streams: while a turn streams, `histFollow` pins the viewport to the newest content every render, so the user always sees the latest tool call / answer land. Scrolling up to read an earlier result breaks follow and the reading position holds while the stream keeps producing below; a keypress that reaches the newest content re-engages follow, as does starting a fresh turn. Follow is off while paused, so new deltas never yank the viewport away from the result the user is reading.
- **Tool-result byte cap** — the shared byte budget (`DefaultByteCap`, 64 KiB) every tool result is measured against before its bytes enter message history: over-budget results are deterministically head-truncated with an explicit `+N bytes truncated` marker, while the full raw result stays available through the TUI expand seam — only the *delivered* form is capped.
- **Expanded-view mode** — the persistent Ctrl+E transcript mode (`expandAll`) that renders every tool entry full-size. An `edit`/`write` card replaces its raw result dump with an **inline card diff**: the captured before→after file content runs through the pure-Go diff engine (`internal/diff`) and inline card diff styling inside the card's category-colored left border. A path whose content couldn't be snapshotted falls back to the `[+N, −M]` count summary. Collapsed, the card keeps the one-line `[+N, −M]` delta tag and never leaks file content. Ctrl+E (or the `e` key, which sets the same mode) is the **single expansion mechanism**: the modal changed-file review overlay and its Ctrl+D toggle are gone, so Ctrl+D is deliberately unbound and file-change inspection happens only in-flow on these cards.
- **Thinking suppression** — the per-provider capability to actually stop chain-of-thought on the wire when the thinking toggle is off, declared through the generation-control seam (`GenerationControlThinkingSuppression`, negotiated via `NegotiateGenerationControls`). Both expression forms are suppression: the openai-compatible path omits the `thinking` toggle when off, while the copilot path sends an explicit `thinking:{type:disabled}`. A provider that does not declare the control surfaces a warning that reasoning cannot be disabled instead of silently no-op'ing the toggle.
- **open_in_browser escape hatch** — deliberately **dropped**. The modal review panel's `o` key that handed the focused changed file to the host browser/editor was the only consumer of the TUI's `OpenInBrowser` dependency seam, so both went with the panel. The standalone `open_in_browser` host-side tool (registry-backed) remains for model-invoked opens.
- **Stopped turn** — a running agent turn aborted by the user (esc or ctrl+c in the TUI) at the context-cancellation boundary: the provider stream dies and any running tool is killed, and the engine refuses to open fresh provider work. The partial output stays on screen in its own pane with a stopped marker — distinct from an error — and the next prompt runs normally. The TUI owns the cancel handle; the shared run seam (`runAgent` in `internal/app`) threads that per-turn cancelable context into `Engine.RunAgent` — batch passes `context.Background()` (non-interactive, no stop binding). The engine reports the stop through a sentinel (`ErrStopped`, wrapping `context.Canceled`) that the app adapter maps to the TUI's `Stopped` result flag.
- **TurnDispatch** — the TUI module (`internal/tui/turn_dispatch.go`) owning the turn state machine: context lifecycle for each agent turn (install, cancel, release), streaming delta accumulation into the in-progress assistant message, and `turnDoneMsg` reconciliation (stopped, error, success with or without streaming). Depends on the **Turn** seam — the engine interface (`type Turn func(ctx, prompt, payload) (TurnResult, error)`) — injected at construction via `NewTurnDispatch`. Continuation logic remains on **Model**, not on TurnDispatch.
- **Per-turn event timeline** — the single arrival-ordered event log (`message.events`) recording, in the exact order the model emits them, reasoning deltas, tool starts, tool results, and answer deltas for an assistant turn. `content` and `reasoning` are derived snapshots of that log — recomputed from it while streaming, finalized from the authoritative turn result at completion — so copy-to-clipboard, telemetry, and the OpenCode-gateway `tool_calls` export keep reading unchanged text. Both append seams write to the live `Transcript.timeline` during the turn; `handleTurnDone` commits it onto the turn's assistant message. In the live app the engine listener pushes both kinds onto one FIFO `EventFeed`, so the timeline records engine emission order rather than Bubble Tea's arbitrary command delivery order.
- **Merged transcript flow** — the transcript renderer walking the per-turn event log to emit one continuous block per turn in arrival order, replacing the three separate panes (thinking, tool log, answer). Reasoning reads as a dimmed left-ruled internal monologue (gated by the thinking toggle); tool starts and results render inline at the position their events arrive; the answer lands at the tail in its full-accent pane. `RenderFlow` (`internal/tui/flowrender.go`) is the single deep seam both the committed event log and the live timeline flow through, carrying the committed-vs-live difference as a parameter rather than in closures — so the merged flow is unit-testable on a small event log. Turns with no event log (help/skill/login notes, error notes) fall back to the legacy blocks, rendered through the same single emitters, so header/pane/stopped rendering cannot drift between the flow and legacy paths. The shared row→tool-entry hit-test index works on the merged stream unchanged because the flow records the same `toolRowRange` shape. A committed turn's reasoning snapshot renders exactly once, at its first tool boundary (or the tail when no tool follows). On a live turn the flow flushes each chain-of-thought fragment at the tool boundary it precedes, so reasoning that resumes after a tool call renders as its own interleaved dimmed block — never dropped, never merged into the first block.
- **Phase** — the single derived answer to "what is the agent doing right now", computed on the TUI side (`internal/tui/phase.go`) from the live turn state rather than stored: the turn's busy flag plus what the in-progress assistant stream is doing. The four values are `idle`, `reasoning` (chain-of-thought streaming before the answer), `working` (a turn runs but no assistant text streams yet), and `answering` (answer text flowing; it takes precedence over trailing reasoning). Transcript's `phase()` is the seam the stage-label verb and the live-reasoning panel hang off; the busy indicator's stage verb splits by phase, while the reduced-motion/ASCII fallback stays the static `… thinking` line.
- **Live reasoning panel** — the current turn's reasoning block auto-expands while its chain-of-thought deltas stream, framed in the dimmed streaming thinking-pane border, so the user watches the thinking grow live instead of a static hint; it collapses back to the one-line `🤔 N tok` hint once the turn's answer lands. The expansion is computed at render time from the message's still-streaming state rather than stored, so it needs no stream-exit reset: Enter on the Tab-focused block toggles it during and after streaming, and any reasoning the backend sneaks through a thinking-off turn stays hidden behind the `thinkingRequested` gate.
- **Collapse-by-default + block focus** — chain-of-thought and tool results collapse to their `🤔 N tok` hint / one-line call summary by default (two persisted Settings toggles, `CoTCollapsedByDefault` and `ToolResultsCollapsedByDefault`, both defaulting on), so a large reasoning block can never push tool calls out of view. Per-block expand is keyboard-driven: `Tab` cycles a `focusedBlock` cursor over the collapsible blocks and `Enter` toggles the focused block, with the `▸` marker on the focused head/hint. On a live turn whose chain-of-thought renders as multiple interleaved fragments, each fragment is its own focusable block, so `Tab`/`Enter` collapse or expand a single fragment while the others keep their own state — the per-fragment force is scoped by fragment index and cleared on turn commit or global-mode entry. The global `e` key enters expand-all, `E` enters collapse-all-to-hints, and `Ctrl+E` toggles between expand-all and the default mode; per-block forces beat any global mode.
- **ExpansionState** — the value type (`internal/tui/expansion.go`) that becomes the single owner of Eitri's block-expansion policy: the global `viewMode` plus a per-block expansion force for every collapsible block, reasoning fragments and tool-result entries alike. One query — `expanded(kind, id) bool` — answers whether a block renders open or collapsed: a per-block force beats any global mode, expand-all/collapse-all decide for a force-less block, and otherwise the block follows its kind's collapsed-by-default flag. The `toggle`/`set`/`clear`/`setMode` operations mutate that one policy source, and entering a global mode drops every per-block force. It holds no reference to transcripts or tool logs — callers map their own blocks onto ids — so it can be unit-tested as a state machine. All expansion state (tool-log per-entry flags, reasoning-block forces, live-stream auto-expand) reads and writes the seam instead of scattered leaf flags; the live-stream auto-expand keeps a streaming reasoning block open regardless of mode unless pinned force-collapsed. The now-dead leaf helpers and their duplicate delegation are deleted — every caller toggles through the seam directly.
- **Collapse-focus seam** — the block-focus cursor state lives in its own module (`internal/tui/collapsefocus.go`): the `collapseFocus` value type owns whether the cursor is active and which collapsible block it points at (an index into a caller-supplied block list), with the Tab traversal as a state machine (`focusNext` activates/advances/wraps, and a zero-length list keeps it off) surfaced through one query. The Transcript is a thin delegate: it renders its own block list onto the seam (`collapsibleBlocks()`) and forwards the cursor queries, while block identities and expansion forces remain on `ExpansionState`. The seam is a pure value type — no reference to transcripts, messages, or tool logs — so the Tab-cycle/Enter-toggle cursor is unit-testable on its own.
- **Markdown-rendered reasoning** — the expanded chain-of-thought block funnels through the same `RenderMarkdown` seam as the answer (at `transcriptWidth - 2`), so long single-line reasoning word-wraps instead of overflowing the terminal and code fences/lists keep their structure; the reasoning body frames in the dimmed-italic thinking-pane border so it reads as internal monologue next to the full-accent answer frame. The collapsed-by-default behavior, the Enter-on-focused-block toggle, and the clipboard plain-text form are unchanged.
- **Tool-activity pulse fallback** — the busyPulse accent flash on tool starts while thinking is off: with no chain-of-thought stream to derive the arrival pulse from, each tool beginning execution arms the same brief accent pulse so the running tool entry's head flashes the agent accent instead of its category hue. The same armed pulse flashes the bottom busy band, which is the only "something started" signal on a turn whose chain of thought is collapsed and whose tool card is not yet in view. Gated to thinking-off turns and to the motion gate, so the reduced-motion/ASCII fallback keeps the static `… thinking` indicator; a completed entry settles back to its category hue immediately.
