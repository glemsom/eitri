# ADR 0003 — Session compaction budget & eviction policy

- Status: accepted
- Date: 2026-08-12
- Related: ticket [Session compaction budget & eviction policy (#21)](https://github.com/glemsom/eitri/issues/21); informed by research ticket [Agent session compaction patterns (#16)](https://github.com/glemsom/eitri/issues/16) and couples with [Prompt-caching best practice (#12)](https://github.com/glemsom/eitri/issues/12), [Thinking/reasoning-model interaction (#17)](https://github.com/glemsom/eitri/issues/17), [Skill activation best practice (#14)](https://github.com/glemsom/eitri/issues/14), and [Skill-pack payload mechanics (#20)](https://github.com/glemsom/eitri/issues/20).

## Context

Long-agent sessions outgrow context. The research (#16) showed mature runtimes
(opencode, Pi, Claude Code, Docker Agent, OpenAI SDK) converge on one shape:
compact **proactively on streamed token usage** at `context − reserve`, keep the
newest turns verbatim, replace the older body with a progressive **anchored LLM
summary** re-injected at the head of the new prefix, and treat every compaction
as a hard **prompt-cache break**.

Eitri's primary provider is `deepseek-v4-flash` with a ~1M-token context. Cache
economics matter here: a cache hit is ~50× cheaper than a miss ($0.0028 vs
$0.14/1M input), and compaction forces one cold prefix re-warm (~20k tokens ≈
$0.0028) — about a fraction of a cent per event. So the governing trade-off is
*fresh-tail cost vs. old-body summary cost*, and compacting *early* (cheaper
verbatim turns at hit-vs-miss rates) wins over waiting to the last moment.

This ADR fixes Eitri's compaction **budget** (when to fire) and **eviction
policy** (what to drop and what to keep), and the summary/telemetry behavior
surfacing on each compaction.

## Decision

1. **Auto-compact by default, at 80% context utilization.** Eitri tracks
   streamed `usage` per turn (already forced on by the Chat-Completions work,
   #11) and, when `used_tokens ≥ 0.8 × context_window`, runs the compaction
   engine automatically. No ask-the-user prompt; the human isn't interrupted to
   approve a sub-cent operation. The effective reserve at default is
   `0.2 × context` (≈200k tokens at 1M ctx), which still amply covers the next
   assistant + tool round-trip. 80% is Eitri's default; the fraction is
   configurable, not hardcoded.

2. **One unified compaction engine, two triggers.** The same engine runs from
   either trigger: the proactive **80%-threshold** above, or an **emergency
   overflow** path that fires on a provider `400`/context-overflow error
   *below* the threshold. Both evict oldest turns and rebuild the anchored
   summary head — no separate code path for the overflow case.

3. **Eviction: keep a verbatim tail, drop the oldest body.** Keep the newest
   turns verbatim within `keep_recent_tokens ≈ 8,000` and at least
   `tail_turns = 2` assistant+user turn-pairs, which act as a **hard floor** —
   never evict below the last two pairs even if they exceed the 8k budget
   (the immediate work's correctness beats token savings at 1M ctx). The tail
   budget includes `reasoning_content`, so thinking from in-flight tool-call
   turns is never evicted (#17 invariant).

4. **Anchored LLM summary.** The evicted old body is replaced by a progressive
   anchored summary — `## Objective` / `## Next Move` structure — capped at
   4,096 tokens, re-injected at the **head** of the new prefix, where it becomes
   the new byte-stable cache prefix (#12 invariant). The summary is generated by
   the **same `deepseek-v4-flash` provider** as a separate non-tool call (≈ sub-cent
   at $0.28/1M output; NOT worth a second embedder/model for compaction). If the
   summary prompt alone would not fit, **fail-safe skip**: compact the body and
   proceed without a new summary rather than risk a malformed prefix.

5. **Skill-content ring-fence.** Optional `prune` (default **off**) that, when
   enabled, never removes `["skill"]`-tagged content and never truncates output
   silently (`+N more`-style markers only — #13 invariant). The skill-content
   tags double as this ring-fence (aligned with #16 and #20).

6. **Cache effect handed to the session key.** Compaction is a hard cache
   break: keep the session cache key, treat the content prefix as cold. Per-turn
   `usage.prompt_cache_hit/miss_tokens` is instrumented (#11) to surface the
   post-compaction re-warm.

7. **TUI surfacing, read-only.** A `[compacted]` status entry and a live cache
   hit-ratio gauge in the TUI (Charm stack, #18). Purely informational — never
   blocks the agent, no user-facing prompt.

## Consequences

- Compaction happens silently and rarely at default (80% of 1M), each event
  costing ≈ fraction of a cent, so the human is never interrupted and token
  overhead to react to compaction is negligible.
- The non-negotiable eviction floor (2 tail pairs, reasoning included) and the
  skill ring-fence protect correctness and skill-content during compaction.
- Single engine + two triggers keeps the overflow path on the same, tested
  compaction code; a new summary-embedding model is explicitly avoided.
- Telemetry makes post-compaction cache re-warm observable, closing the loop on
  #12's hit-ratio requirement.
