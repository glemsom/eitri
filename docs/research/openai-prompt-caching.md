# OpenAI prompt caching

> **Historical external reference.** This records OpenAI-native behavior, not OpenCode Go behavior. For Eitri’s current implementation and blocked provider validation, see [Prompt-cache current status](prompt-cache-status.md).

**Findings verified against OpenAI’s official documentation and API reference on 2026-09-27.** This note deliberately separates the Chat Completions and Responses APIs.

## Protocol behavior shared by supported models

- Prompt caching is automatic: it is enabled by default on supported models. It reuses a cached KV-state only when the **entire rendered prefix** matches an available cache entry; it is not a token-by-token similarity cache. The rendered context includes OpenAI-provided instructions, developer messages, tool definitions, and conversation history. [Prompt Caching guide — why and what is cached](https://developers.openai.com/api/docs/guides/prompt-caching#why-prompt-caching-matters)
- A prefix must reach the model’s cacheable minimum before it can be saved. For GPT-5.6 and later that is **1,024 visible input tokens**; OpenAI hidden-system tokens do not count. For earlier models the minimum varies with request settings, including tools, images, output schemas, reasoning effort, and verbosity. [How caching works](https://developers.openai.com/api/docs/guides/prompt-caching#how-caching-works) · [model differences](https://developers.openai.com/api/docs/guides/prompt-caching#summary-of-model-differences)
- Cache entries are temporary, and reuse refreshes their lifetime without an additional cache-write charge. Cache reuse is scoped to an organization and processing region. [Cache lifetime and location](https://developers.openai.com/api/docs/guides/prompt-caching#cache-lifetime)

| Topic | Chat Completions | Responses |
| --- | --- | --- |
| Cache-hit usage field | Read `usage.prompt_tokens_details.cached_tokens`. [Chat Completions create reference](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create/) | Read `usage.input_tokens_details.cached_tokens`. For GPT-5.6+, also read `usage.input_tokens_details.cache_write_tokens`. [Responses create reference](https://developers.openai.com/api/reference/resources/responses/methods/create/) · [usage examples](https://developers.openai.com/api/docs/guides/prompt-caching#request-parameters-and-response-usage) |
| GPT-5.6+ breakpoint controls | Supports `prompt_cache_options` and content-block `prompt_cache_breakpoint`; default `mode` is `implicit`. Implicit mode adds one implicit breakpoint and can write the latest three explicit breakpoints; explicit mode writes the latest four explicit breakpoints. With explicit mode and no explicit breakpoint, the request does not use prompt caching. [Chat Completions create reference](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create/) | The same controls and default mode apply. For implicit mode, the guide describes the breakpoint as the end of the latest eligible message; use `prompt_cache_breakpoint: {"mode":"explicit"}` in a supported input content block for an explicit boundary. [Responses create reference](https://developers.openai.com/api/reference/resources/responses/methods/create/) · [caching guide](https://developers.openai.com/api/docs/guides/prompt-caching#how-caching-works) |
| Prewarming | Not documented in the caching guide. | A Responses request can set `prompt_cache_options.prewarm: true` to prepare a cache without generating output, then send the real request with the same prefix. [Prewarm the cache](https://developers.openai.com/api/docs/guides/prompt-caching#prewarm-the-cache) |

## Concrete practices

1. **Make the beginning immutable.** Put stable developer instructions, stable tool definitions/schemas, and shared reference material first; put timestamps, per-user data, and other changing content later. Changing a tool name, description, schema, or ordering changes the prefix. [Cached-prefix inputs](https://developers.openai.com/api/docs/guides/prompt-caching#what-is-the-prompt-cache) · [preserve conversation history](https://developers.openai.com/api/docs/guides/prompt-caching#preserve-conversation-history)
2. **Append, do not rewrite.** Preserve earlier messages and tool results and append new turns. Summarization, compaction, or truncation changes the prefix from the changed token onward and can reset reuse. [Preserve conversation history](https://developers.openai.com/api/docs/guides/prompt-caching#preserve-conversation-history)
3. **For GPT-5.6+, choose boundaries intentionally.** Both APIs support implicit and explicit breakpoints. Use implicit mode for ordinary growing threads; put explicit breakpoints immediately after reusable material when later material changes frequently, so that material is not needlessly cache-written. A request can create at most four cache writes. [Breakpoint behavior](https://developers.openai.com/api/docs/guides/prompt-caching#how-caching-works) · [Chat Completions reference](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create/) · [Responses reference](https://developers.openai.com/api/reference/resources/responses/methods/create/)
4. **Use a stable `prompt_cache_key` for its model-appropriate purpose.** Before GPT-5.6, give related requests with a reusable prefix the same stable key to improve routing; it neither pins a request to a machine nor guarantees a hit. OpenAI recommends about 15 requests/minute per key for busy groups and deterministic partitioning above that. On GPT-5.6+, routing is automatic; keys are optional and useful for separate customer/user/workspace accounting and reducing cache-hit probing across groups. [Prompt cache keys](https://developers.openai.com/api/docs/guides/prompt-caching#prompt-cache-keys) · [Responses parameter](https://developers.openai.com/api/reference/resources/responses/methods/create/)
5. **Set retention only where applicable.** GPT-5.6+ uses `prompt_cache_options.ttl`; its only supported value and default is `"30m"`, making a prefix eligible for at least 30 minutes after its latest write or reuse. Earlier models use `prompt_cache_retention`: `"in_memory"` is typically active after 5–10 idle minutes (up to one hour), while `"24h"` is typically available around 30 minutes and may persist up to 24 hours; support and defaults depend on model and organization retention policy. [Cache lifetime](https://developers.openai.com/api/docs/guides/prompt-caching#cache-lifetime)
6. **Measure real reuse, not presumed reuse.** For Responses, track cached tokens, cache-write tokens, total input tokens, latency, and realized cost; calculate token cache-hit rate as total cached tokens divided by total input tokens, grouped by a useful dimension such as user, workspace, or day. Use the Prompt Caching Dashboard for cache-read hit rates. For Chat Completions, use its API-specific cached-token field above with total prompt tokens for equivalent monitoring. [Monitor cache performance](https://developers.openai.com/api/docs/guides/prompt-caching#monitor-cache-performance) · [Chat Completions create reference](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create/)
