## Ordering and breakpoint placement

The engine constructs the request in this exact order: byte-stable system head, optional skill index, optional repository instructions, then records that boundary as `StaticPrefixLen`; the per-run workspace directive follows; then session history; then the current user message. This is the ordering assumption behind cross-run/session reuse: volatile workspace state is deliberately *after* the static breakpoint. [internal/engine/engine.go:247-267](../../internal/engine/engine.go#L247-L267).

For OpenCode Chat Completions, automatic placement stamps at most two cumulative breakpoints:

1. the last static-prefix message (`StaticPrefixLen - 1`), or, if no valid declared boundary exists, the final leading system message; and
2. the final message in the request (unless it is already the first breakpoint).

It copies the message slice before stamping. An out-of-range declared prefix produces no markers. This policy assumes a cache write is cumulative through its breakpoint and that the moving tail seeds the next incremental turn. [internal/provider/chatdialect.go:198-257](../../internal/provider/chatdialect.go#L198-L257). Tests cover declared placement, system-prefix fallback, coalescing, and invalid bounds. [internal/provider/chatdialect_test.go:239-325](../../internal/provider/chatdialect_test.go#L239-L325).

Markers are suppressed for non-OpenCode providers, for lowercase `glm-`/`zhipu-` model substrings, and whenever **any** request message or tool already has a marker. [internal/provider/chatdialect.go:219-224](../../internal/provider/chatdialect.go#L219-L224), [internal/provider/chatdialect.go:259-278](../../internal/provider/chatdialect.go#L259-L278). The GLM guard is case-sensitive.

## Tools

`CacheControl` is representable on both canonical messages and tools. Chat Completions emits it directly on either object; Anthropic maps message controls to system/text blocks and tool controls to tool definitions. Tool-schema strictness preserves an existing tool marker. [internal/provider/provider.go:65-125](../../internal/provider/provider.go#L65-L125), [internal/provider/chatdialect.go:166-176](../../internal/provider/chatdialect.go#L166-L176), [internal/provider/anthropic.go:123-141](../../internal/provider/anthropic.go#L123-L141), [internal/provider/anthropic.go:199-211](../../internal/provider/anthropic.go#L199-L211).

Automatic OpenCode policy stamps **messages only**. A caller-supplied marker on a tool disables both automatic message markers; it does not cause automatic tool-manifest caching. Explicit message/tool serialization is tested, but there is no test of automatic policy with the normal stable toolset or tool-marker precedence. [internal/provider/chatdialect_test.go:125-150](../../internal/provider/chatdialect_test.go#L125-L150), [internal/provider/chatdialect_test.go:373-402](../../internal/provider/chatdialect_test.go#L373-L402).

## Session keys and retention

The application uses the session GUID as the cache key. Each turn reads the live key; `/new` mints a new GUID, invokes the app callback that clears the old in-memory history, and resets TUI telemetry. The prior on-disk session remains auditable and is not pruned. Engine history is keyed in memory by that same value; clearing drops only that history. [internal/app/app.go:258-263](../../internal/app/app.go#L258-L263), [internal/app/tui.go:120-135](../../internal/app/tui.go#L120-L135), [internal/app/tui.go:32-57](../../internal/app/tui.go#L32-L57), [internal/tui/model.go:675-695](../../internal/tui/model.go#L675-L695), [internal/engine/engine.go:516-545](../../internal/engine/engine.go#L516-L545).

`"24h"` is the sole explicit retention value and is always emitted for OpenCode Chat Completions, even if no key is present. It is also the TTL in automatic `cache_control`; no equivalent retention/key policy exists on the Anthropic wire. [internal/provider/chatdialect.go:179-201](../../internal/provider/chatdialect.go#L179-L201).

## Telemetry

* Chat-Completions usage accepts either DeepSeek `prompt_cache_hit_tokens`/`prompt_cache_miss_tokens` or OpenAI `prompt_tokens_details.cached_tokens`. If no cache shape appears, all prompt tokens become misses; a hit-only report infers `prompt - hit` misses. [internal/provider/provider.go:213-258](../../internal/provider/provider.go#L213-L258).
* Anthropic reports `cache_read_input_tokens` as hits and calculates misses as `input_tokens - cache_read_input_tokens`; `cache_creation_input_tokens` is parsed but not used independently. [internal/provider/anthropic.go:320-325](../../internal/provider/anthropic.go#L320-L325), [internal/provider/anthropic.go:405-420](../../internal/provider/anthropic.go#L405-L420).
* Responses reports `input_tokens_details.cached_tokens` as hits. A present `cached_tokens:0` marks the cache shape as assigned, but finalization infers misses only for a positive hit; this yields `hit=0, miss=0` despite input tokens. [internal/provider/responses.go:375-384](../../internal/provider/responses.go#L375-L384), [internal/provider/provider.go:245-257](../../internal/provider/provider.go#L245-L257). Copilot fixtures include this zero-hit shape without asserting normalized misses. [internal/provider/copilot_test.go:281-285](../../internal/provider/copilot_test.go#L281-L285).
* One final usage value per turn is forwarded to the TUI, which sums hits/misses and computes `hit / (hit + miss)`. Consequently the Responses zero-hit case removes cold input from the ratio denominator. [internal/engine/engine.go:404-420](../../internal/engine/engine.go#L404-L420), [internal/app/tui.go:167-170](../../internal/app/tui.go#L167-L170), [internal/tui/telemetry/telemetry.go:62-99](../../internal/tui/telemetry/telemetry.go#L62-L99).

## Risks and gaps

1. **Inconsistent OpenCode coverage (high):** Anthropic-routed OpenCode models get only the session header, not the Chat-Completions breakpoint/key/retention policy. They may serialize caller-provided markers, but Eitri does not establish its intended automatic static-prefix/tail caches for them.
2. **Nonportable identifier/field disclosure (medium):** custom Chat endpoints receive `prompt_cache_key`; custom Anthropic endpoints receive `X-Opencode-Session`. Strict endpoints can reject unknown extensions, and both expose the session GUID outside the OpenCode provider family.
3. **Toolset cache policy is unproven (medium):** the stable toolset is potentially a material prompt prefix, yet it is never automatically marked. Conversely, one explicit tool marker suppresses all automatic message placement. Provider semantics and desired precedence need an integration test/spec.
4. **Copilot cold-cache telemetry is wrong (high):** explicit zero cached tokens become neither hit nor miss, making the aggregate denominator and displayed cache efficiency unreliable.
5. **Anthropic cache-write accounting is ambiguous (medium):** cache-creation tokens have no independent representation; current miss arithmetic assumes `input - cache-read` is the desired cold/cache-write total. Validate that assumption against the target gateway’s billing/usage contract.
6. **Model exclusion is brittle (low):** GLM/Zhipu rejection matching is lowercase substring-only; mixed-case aliases can receive unsupported `cache_control`.
