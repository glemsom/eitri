# Anthropic prompt caching

> **Historical external reference.** This records Anthropic-native behavior, not OpenCode Go behavior. For Eitri’s current implementation and blocked provider validation, see [Prompt-cache current status](prompt-cache-status.md).

## Enable and place cache breakpoints

- The Messages API defines `cache_control` as `{"type":"ephemeral","ttl":"5m"|"1h"}`; the API response `usage` includes cache-creation and cache-read token fields. [Anthropic API Reference: Messages](https://docs.anthropic.com/en/api/messages)

- Use **automatic caching** by adding one top-level `cache_control`; Anthropic places its breakpoint on the last cacheable block and advances it as a conversation grows. Use **explicit caching** by attaching `cache_control` to an individual content block when the cached boundary must be controlled precisely. [Anthropic: Prompt caching — Automatic caching](https://docs.anthropic.com/en/docs/build-with-claude/prompt-caching#automatic-caching)
- A cache entry is the cumulative prefix, ordered **tools → system → messages**, through the marked block. Put stable tool definitions, instructions, context, and examples first, then mark the last block shared by the requests that should hit the entry. [Anthropic: Prompt caching — Structuring your prompt](https://docs.anthropic.com/en/docs/build-with-claude/prompt-caching#structuring-your-prompt)
- Cache writes occur only at a breakpoint. Therefore, for a static prefix followed by a timestamp, per-request context, or new user message, mark the final static block—not the changing block. [Anthropic: Prompt caching — How automatic prefix checking works](https://docs.anthropic.com/en/docs/build-with-claude/prompt-caching#how-automatic-prefix-checking-works)
- A request may have at most four breakpoints. Use more than one for sections that change at different rates or to preserve hits as a growing conversation moves beyond the 20-position backward lookup; top-level automatic caching consumes one of the four slots when combined with explicit markers. [Anthropic: Prompt caching — When to use multiple breakpoints](https://docs.anthropic.com/en/docs/build-with-claude/prompt-caching#when-to-use-multiple-breakpoints) [Anthropic: Prompt caching — Combining with block-level caching](https://docs.anthropic.com/en/docs/build-with-claude/prompt-caching#combining-with-block-level-caching)

## Lifetime and conversation growth

- `{"type":"ephemeral"}` has a five-minute TTL by default. A cache read refreshes its lifetime without an additional refresh charge; the lifetime starts when the request starts, so response streaming time consumes it. [Anthropic: Prompt caching](https://docs.anthropic.com/en/docs/build-with-claude/prompt-caching)
- Set `{"type":"ephemeral","ttl":"1h"}` for a one-hour entry. A five-minute cache is preferable for prompts reused within five minutes because reads keep it fresh; Anthropic recommends one hour when reuse is likely after five minutes but within an hour or latency beyond five minutes matters. [Anthropic: Prompt caching — 1-hour cache duration](https://docs.anthropic.com/en/docs/build-with-claude/prompt-caching#1-hour-cache-duration)
- For incremental multi-turn requests, automatic caching moves the cached boundary forward: the prior prefix is read and newly appended content is written. With explicit markers, lookup checks at most 20 positions per breakpoint; consecutive `tool_use` blocks and consecutive `tool_result` blocks each count as one position. Add an earlier/nearer breakpoint before the last write falls outside that window. [Anthropic: Prompt caching — How automatic caching works in multi-turn conversations](https://docs.anthropic.com/en/docs/build-with-claude/prompt-caching#how-automatic-caching-works-in-multi-turn-conversations) [Anthropic: Prompt caching — How automatic prefix checking works](https://docs.anthropic.com/en/docs/build-with-claude/prompt-caching#how-automatic-prefix-checking-works)

## Tools and eligibility

- Tool definitions in `tools` are cacheable. Since tools precede system and messages in the cache hierarchy, changing a tool's name, description, or parameters invalidates the tool cache and all downstream cache levels; keep frequently reused definitions stable. [Anthropic: Prompt caching — What can be cached](https://docs.anthropic.com/en/docs/build-with-claude/prompt-caching#what-can-be-cached) [Anthropic: Prompt caching — What invalidates the cache](https://docs.anthropic.com/en/docs/build-with-claude/prompt-caching#what-invalidates-the-cache)
- The cacheable-prefix minimum is model-specific: current documented thresholds range from 512 to 4,096 tokens. A shorter marked prefix is processed without caching and without an error; if both cache counters are zero, it was not cached (commonly because it missed the threshold). [Anthropic: Prompt caching — Cache limitations](https://docs.anthropic.com/en/docs/build-with-claude/prompt-caching#cache-limitations)
- A newly written entry becomes available only after the first response begins, so delay parallel followers until then if they need a hit. [Anthropic: Prompt caching — Cache limitations](https://docs.anthropic.com/en/docs/build-with-claude/prompt-caching#cache-limitations)

## Observe and operate it

- Inspect `usage.cache_creation_input_tokens` (tokens written), `usage.cache_read_input_tokens` (tokens read), and `usage.input_tokens` (uncached suffix tokens); streaming exposes them in `message_start`. Total input tokens equal the sum of those three values. [Anthropic: Prompt caching — Tracking cache performance](https://docs.anthropic.com/en/docs/build-with-claude/prompt-caching#tracking-cache-performance)
- Start with automatic caching for ordinary multi-turn work; use explicit markers for independently changing regions. Keep cached content at the start, make the cached prefix byte-for-byte equivalent (including images), preserve marker placement and relevant request settings, and monitor hit rates and cache diagnostics. [Anthropic: Prompt caching — Best practices for effective caching](https://docs.anthropic.com/en/docs/build-with-claude/prompt-caching#best-practices-for-effective-caching) [Anthropic: Prompt caching — Cache storage and sharing](https://docs.anthropic.com/en/docs/build-with-claude/prompt-caching#cache-storage-and-sharing) [Anthropic: Prompt caching — Troubleshooting common issues](https://docs.anthropic.com/en/docs/build-with-claude/prompt-caching#troubleshooting-common-issues)
